# Which missing benchmarks can we add?

**The original review found an implementation path or a needed durability test for twelve of 13 skipped client/case combinations.** The remaining case is Turso’s exact row-level revocation contract. Missing adapters and failed experiments are work to do, not evidence that a product lacks a feature.

This review covers every current skipped/failed case, both missing local-commit measurements, and the three Turso cases with earlier failures: [22 reviewed entries and source checksums](../../results/diagnostics/final-publication/COVERAGE-REVIEW.json). **Six repaired cases now have validated publication measurements:** Electric relationships/reopen, Jazz relationships, Zero reopen, TanStack crash recovery and Rust attachments. [Verification receipts](../../results/diagnostics/coverage-fixes/VERIFICATION.json) preserve successes and rejected development attempts. Those development runs stay separate. The [new publication](../../results/reports/coverage-fixes/RESULTS.md) replaces exactly these six cases in the README with one predeclared run each (n=1); run-to-run variability is unknown.

| Case | Finding and next step |
| --- | --- |
| Electric related queries | Verified: native shapes load all three tables; application lookup/order indexes serve joins and per-query aggregation. Full fixture and screen output checks pass. |
| Jazz related queries | Verified: indexed native UUID references, nested project/organization includes, application dashboard aggregation, and a separate edge-durable seed process. All 100,000 tasks and both outputs validate. |
| Electric offline reopen | Verified: the application SQLite cache reopens in a new process with both routes blocked. Shape transport starts lazily; every persisted row and the first screen validate. |
| Zero offline reopen | Verified using the public native `SQLiteStore` and a Bun platform delegate. Two seconds of preparation allow scheduled persistence before close; close the client before disposing views. All 2,000 rows and the native screen survive offline reopen. The original memory profile was a harness choice. |
| TanStack crash recovery | Verified: native executor plus SQLite `StorageAdapter`, WAL and synchronous FULL. After SIGKILL, the SDK restores all 1,000 edits and original transaction/idempotency identities, then replays them to an independent reader. The harness does not reconstruct or replay transactions. |
| Zero crash recovery | Test the native SQLite store under forced process death before deciding. Cached reads do not prove queued-write durability. Zero accepts writes while connecting but rejects them after becoming disconnected; keep the canonical short outage and default connection policy. [Connection behavior](https://zero.rocicorp.dev/docs/connection). |
| PowerSync attachments | Implement its native `AttachmentQueue`, filesystem storage and a shared object-store adapter. The installed Node SDK successfully staged a 2 MiB file and retained its queued record across a clean database reopen in our [local probe](../../results/diagnostics/final-publication/CAPABILITY-PROBE.json). Upload/retry remains untested. [Official attachment integration](https://docs.powersync.com/client-sdks/advanced/attachments). |
| Jazz attachments | Implement the installed v2 `createFileFromBlob` / `loadFileAsBlob` path with `files` and `file_parts`. Its chunked sync differs from S3 uploads: use equivalent byte/durability milestones, not an HTTP-PUT requirement. Classic Jazz FileStream documentation is not evidence for this alpha version. |
| Electric, TanStack, Zero and Turso attachments | Add a shared application-owned object-transfer queue and let each product sync file references. These are viable application workflows. Clearly distinguish the shared uploader from PowerSync/Jazz/Syncular product-owned transfer logic; otherwise a file-transfer table can misleadingly measure the same helper four times. |
| Turso access revocation | Keep this exact case unavailable: the pinned local server syncs a database, without equivalent per-actor row revocation that preserves server rows and another actor’s access. Database-per-user and application-driven purge change the workload. [Partial sync](https://docs.turso.tech/sync/partial) fetches database pages lazily; it is not an authorization filter. |
| Electric local commit | Not applicable to the direct-to-server write profile. A separate SQLite-outbox profile can expose a local commit, but that is application-owned behavior. [Electric write patterns](https://electric.ax/docs/sync/guides/writes). |
| TanStack local commit | Missing instrumentation. Its optimistic local update can be timed, but must be called local visibility. For durable local commit, use a durable queue receipt; `isPersisted` includes remote settlement. Apply the same milestone definition to all clients. |

Three Jazz timeout cases remain investigations, not skips: isolate Jazz cold-startup costs and run warm startup independently; trace Jazz’s divergent deletion state; distinguish Jazz query visibility from native cache purge. Rust attachments now pass the complete upload/retry/download/interruption contract after fixing dropped early frames in the asynchronous WebSocket handshake. Regression tests cover frame order, close-before-ready and a bounded queue; the exact historical timeout has no captured frame trace, so a successful rerun alone does not prove its cause. The [timeout review](./tuned-publication-failures.md#timeout-review) records what is confirmed. Earlier Turso disk failures need a preflight storage budget; the prior connection failure still needs endpoint traces.

The optional Chromium adapter also implements only Electric and Zero collaboration. Its other combinations are browser-harness gaps, not product limitations. A native Rust executable cannot be treated as a browser SDK.

Remaining implementation work is Zero crash recovery, native PowerSync/Jazz attachments and the TanStack local-commit milestone. For the four products without a built-in byte uploader, decide whether a separately labelled application-uploader comparison adds useful information. The six replacements used one publication round each. Any further collection must predeclare at most three rounds per changed case. Admit success only after full output validation; preserve failures and never pool changed configurations with the old samples.
