# Failures in the corrected collection

These reviews concern the three-attempt SQL campaign using Syncular 0.17.0, started on 2026-09-08 at 22:58 UTC. They remain attached to specific attempts. [Current coverage](../../COVERAGE.md) includes successful, unavailable and failed outcomes; the examples below are not product failure rates.

PowerSync missed initial client readiness before the intended offline replay, restart, conflict, fanout or reconnect work. Its replica-reopen attempts instead exceeded setup sync-command deadlines before reopening. The captured logs do not establish the cause. These attempts provide no latency for the intended workload. Fanout setup failures before reader creation cannot establish a reader-count scaling limit. The [individual setup reviews](../../results/diagnostics/tuned-v017-publication-failures/campaign-2026-09-08T22-58-56-419Z/CASE-REVIEWS.json) preserve each case and its causal limits. Per-client sync and read milestones, followed by a separate fresh-versus-retained storage experiment, would distinguish setup causes.

All three PowerSync bootstrap attempts missed the 90-second deadline at the first 1,000-task client. Each recorded 18 zero progress counts, while about 179 MB, 196 MB and 179 MB of response traffic crossed the open gate. None validated a first screen or complete dataset. The [first](../../results/diagnostics/tuned-v017-publication-failures/campaign-2026-09-08T22-58-56-419Z/0049/INSPECTION.json), [second](../../results/diagnostics/tuned-v017-publication-failures/campaign-2026-09-08T22-58-56-419Z/0102/INSPECTION.json) and [third](../../results/diagnostics/tuned-v017-publication-failures/campaign-2026-09-08T22-58-56-419Z/0132/INSPECTION.json) startup reviews preserve the observations and timing limits. The cause remains unresolved.

All three Syncular Rust attachment attempts timed out during reader preparation before any upload variant began. A WebSocket-readiness race is a supported hypothesis: the benchmark server discards messages until its async session setup finishes, while native connect can return before the server's `hello`. None captured a frame trace proving that this happened. The [final attempt review](../../results/diagnostics/tuned-v017-publication-failures/campaign-2026-09-08T22-58-56-419Z/0118/INSPECTION.json) records the same preparation timeout before any attachment variant. The [inspection and copied source](../../results/diagnostics/tuned-v017-publication-failures/campaign-2026-09-08T22-58-56-419Z/0030/INSPECTION.json) explain the evidence and the proposed buffering experiment. This outcome supplies no attachment transfer measurement.

Each inspection sits beside its raw result, capture receipt and service logs. Further diagnostics run after fixed collection and stay separate from the comparison samples. [Earlier failure reviews](../history/README.md) belong to the withdrawn campaign.

Turso’s connected-fanout trial 1 and reconnect-storm trial 2 completed their five-reader subcases, then failed during 25-reader setup with `pwrite: no storage space`. These are environment failures; the exact peak footprint was not sampled. Both attempts count toward the three-attempt cap. The [maintenance record](../../results/diagnostics/publication-index-review/MAINTENANCE-PAUSE.json) documents a pause between attempts, lossless archives of idle stores and old working copies, and removal of unused compilation intermediates. The same campaign resumed without changing measured source.

Turso’s second replica-reopen attempt failed earlier, during initial sync, when fetch reported an unexpectedly closed socket. Its [setup review](../../results/diagnostics/tuned-v017-publication-failures/campaign-2026-09-08T22-58-56-419Z/0061/INSPECTION.json) records an open gate and matching server broken-pipe logs. Those observations do not establish which side closed the connection or why. This remains unexplained and supplies no reopen latency; it is not attributed to the separate disk failures.
