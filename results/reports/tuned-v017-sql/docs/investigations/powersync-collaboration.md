# PowerSync collaboration: upload scheduling needs a separate experiment

PowerSync's first two corrected collaboration trials measured reader-visible p50 values of **1,005.13 ms and 982.51 ms**. Each trial used 200 tasks, five warmup writes and 50 measured writes. The [inspection record](../../archive/files/results/diagnostics/powersync-collaboration-throttle/INSPECTION.json.gz) binds those results and the inspected SDK files to the campaign's recorded source and dependency identities. This review covers those two attempts; the [current results](../../RESULTS.md) show subsequent collection.

The benchmark connects without overriding the SDK's upload settings. Installed PowerSync Node 1.0.0 uses shared-internals 1.2.0, whose default `crudUploadThrottleMs` is **1,000 ms**. Both its TypeScript source and emitted JavaScript contain that default. The upload loop starts its queue drain and throttle delay together, waits for both, then waits for a new CRUD notification. The delay overlaps upload work, so adding one second to each operation would misdescribe the code.

Upload scheduling is therefore a **supported hypothesis** for part of the delay. These trials contain no timestamped upload-loop, checkpoint or reader-apply trace that could establish its contribution. Server acceptance occurs when the mutation backend responds successfully; an independent reader observes the update through local SQL polling. Subtracting their p50 values does not measure a specific pipeline stage.

An application choosing a sync client needs to know whether this latency follows from a configurable scheduling choice. After fixed collection, a separate diagnostic should timestamp queue notification, upload start, backend response, checkpoint receipt and reader apply. Compare the default with one declared, supported throttle override while holding the other conditions constant. Preserve the original attempts and report the diagnostic separately. Until that experiment exists, this report makes no claim about achievable PowerSync latency with different settings.
